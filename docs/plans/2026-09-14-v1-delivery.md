# Enterprise Query Agent v1 施工交接

> For agentic workers: use the available executing-plans workflow for staged implementation. 本文件由策略 session 編製；依使用者分工提供設計、檔案責任與驗收要求，不預寫實作碼。實作 session 在各階段依現行環境細化測試與函式。

**Goal:** 完成有限電商領域的中文資料查詢工作台與一次可核對的三方法研究。

**Architecture:** 中文問題 → 業務計畫／澄清 → catalog 驗證與 SQL 編譯 → 共用唯讀執行控制 → 數字事實與證據 → UI。三方法比較共用資料、額度與底層執行控制。

**Tech Stack:** Python 3.12、uv、FastAPI、Pydantic、PyMySQL、SQLGlot、MySQL 8.4、HTML/CSS/JavaScript、pytest。依安裝當日官方支援鎖定依賴，不照抄前作整包 ML 依賴。

## Global Constraints

- 以 specs/2026-09-14-v1-design.md 為契約來源；不修改前作 checkout 或 DB。
- 每筆任務最多 2 輪澄清、3 次模型呼叫、3 條業務 SELECT；每 SQL 5 秒、每任務 60 秒實際處理時間（等待使用者澄清暫停計時）、結果 200 列。
- 第一個開發 session 完成 M1–M3 的 mock／離線工程，不執行正式保留题或發布。
- M1–M3 工程完成不依賴 provider key；M4 另有明確模型、實際價格與使用者同意的預算。
- 不在公共 source 放私人路徑、憑證、raw CSV 或未審查 provider traces。

## 建議檔案責任

| 路徑 | 責任 |
|---|---|
| pyproject.toml / uv.lock | 精簡、可重建的應用與測試依賴 |
| compose.yaml / db/bootstrap/ | 新案獨立 MySQL、schema、角色與資料匯入 |
| scripts/bootstrap_data.py | 核對目的 DB 身分、載入合成／指定 CSV、生成 manifest |
| data/synthetic/ / provenance/ | 公開合成資料、來源檔案清單與 attribution；不存真實 raw data |
| catalog/metrics.yaml | 指標、粒度、分母、維度、coverage policy |
| src/enterprise_query/contracts.py | 設計文件中的 typed request／plan／result／answer |
| src/enterprise_query/catalog.py / compiler.py | 定義驗證、合法組合與參數化 SQL |
| src/enterprise_query/sql_policy.py / executor.py | AST policy、runtime 權限、timeout、結果上限 |
| src/enterprise_query/facts.py | Decimal 聚合與可追溯衍生值，不由 LLM 編造數字 |
| src/enterprise_query/planner.py / providers.py | structured planning、provider adapter、deterministic mock |
| src/enterprise_query/service.py / api.py | request 狀態、revision、額度、API |
| src/enterprise_query/static/ | 單頁問題、澄清、答案、證據介面 |
| eval/ / tests/ | 三方法 runner 與合成契約、實際 DB、API／UI 測試 |
| docs/status.md / reports/ | 真實狀態、驗收紀錄、正式結果與限制 |

這是分工建議，非強制每格都新增一層 abstraction。實作者可合併小模組，保留責任清晰及既定介面語意。

## M1：可信資料與手算正確性

Consumes：來源 commit、CSV 路徑或合成 fixture。Produces：獨立 DB、dataset manifest、catalog、QueryPlan 與 QueryResult 基本契約。

- [ ] 先確認目前目錄與父層不是其他 repo；只在本目錄初始化 Git，設定 repo-local 正式作者。保留既有文件，建立忽略規則。
- [ ] 保存來源 SHA、取得／重用檔案清單與 attribution；明確列來源 CSV 與衍生表。
- [ ] 建立獨立 Compose／bootstrap／SELECT-only runtime 角色，檢查不引用舊容器與 volume。
- [ ] 根據 acceptance-v1 建立合成資料，先寫 D01–D12 的數值測試並確認能抓到預先構造的錯誤 join，再完成 catalog／compiler。
- [ ] 驗證時間、Decimal、null、分母、缺類別與最新評論規則。以獨立計算核對，不只比較生成 SQL 字串。
- [ ] 產出 docs/status.md 的 M1 證據；對應 source／data manifest，不以規劃文字代替執行結果。

驗收：全新独立 DB 的手算結果符合 D01–D12；前作 git status 不變；有不需 Kaggle 或 API key 的合成路徑。

## M2：受控執行與可追溯答案

Consumes：QueryPlan、catalog、獨立 DB。Produces：policy-checked QueryResult、AnswerFact／AnswerEnvelope、明確 terminal failures。

- [ ] 先寫 E01–E06 的 parser 與實際 DB 測試；非法 SQL 必須在適當層被阻擋，合法 CTE／聚合仍可用。
- [ ] 完成共用 SQL policy、runtime permission check、執行限制與查詢取消。
- [ ] 加入結果／SQL／參數／版本證據，實作 Decimal facts、空結果、undefined ratio、截斷說明。
- [ ] 完成 D13–D20 的語意流程 contract tests；mock 只驗 flow，不當自然語言能力得分。
- [ ] 在隔離 DB 以实际 runtime 帳號驗證權限；觀察 timeout 後無殘留 query。禁止只 mock 掉這兩種关键驗證。
- [ ] 執行到此階段必要的單元／integration 檢查，保存 M2 結果並做有意義的小 commit。

驗收：所有任意 SQL 入口共用同一 control；數值依據可追溯，資料版本可核對，錯誤有穩定分類。

- [ ] 完成 FastAPI UI，資料期間與口徑可見、錯誤與空結果可讀、鍵盤能完成操作。
- [ ] 使用六個開發示例錄下中文問題→澄清→答案→證據；mock 示範必須標示 mock。
- [ ] 實測 E07–E12、修改意圖、重送、鍵盤、啟動與埠占用；乾淨來源可用合成資料重現。

## M4：開發模型驗證、凍結與三方法研究（後續 session）

Consumes：工程完成版、真實 Olist 獨立快照、使用者確認的 provider/model 與費用上限。Produces：凍結 manifest、40 任務評估與變體結果。

- [ ] 用至少 24 個開發問題驗證 model adapter／prompt，確認沒有系統性格式或執行失敗；把 D01–D20 及舊十題都列為開發材料。
- [ ] 完成三種方法，檢查 catalog 資訊、澄清腳本、硬性 SQL 控制與額度相同；記錄差異，不能在 scoring 時特別救某一法。
- [ ] 凍結 code、prompt、catalog、data、model、價格、limits、方法順序與 score policy；估算成本後確認本階段額度。
- [ ] 由不修改候選的評估 session 編製並核對 40 題與 12 題的資料變體，封存 gold；如實說明作者重疊限制。
- [ ] 跑一次既定 protocol，保存每題 terminal outcome、成本與證據。中斷保留原 run，依事前恢復規則處理，不挑成功重跑。
- [ ] 輸出全體與分題型結果、共通支援子集、配對失敗、成本／延遲及資料變體結果；不把變體當獨立樣本。

驗收：完整可核對，沒有結果美化；可以 C 不勝過 A/B。實證完成與模型表現高低分開。

## 停止條件

M1–M3 不因缺 API key 一直增加 UI 或基礎建設；M4 不因沒有正增益而持續調參；M5 不因想要更多履歷賣點而加入新功能。發現會改變核心問題、資料庫或評估宣稱的情況，記錄具體原因再交策略 session 判斷。
