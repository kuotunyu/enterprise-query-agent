## 日常使用

明示指標與購買日期，例如「2018年7月GMV」，可避免不必要的來回。相對日期以畫面的 `as_of_date` 計算；「上個月」不會自動跳到資料最後一個月。日期含起日、不含迄日；金額單位 BRL。用「新任務」清除之前的澄清條件。

逾期率、評論均分與回購率要一起看分母和缺值。商品品類／賣家分組可能共用同一筆訂單，分組訂單数不可加總。資料不足、超出支援範圍、模型輸出錯誤與資源逾時都可能使查詢失敗；不要手動換成一個接近的業務問題後仍稱原題成功。

## 展示設計取捨

A 用固定模板限制自由度，支援範圍較小；B 直接產生 SQL，必須通過相同執行防護；C 產生業務計畫，由程式編譯 SQL。三者共用指標定義、模型與資料，但表達能力不同，因此同時報告全部任務與共通支援子集。

SELECT-only 帳號限制資料庫操作，AST 驗證限制 SQL 結構，程式用 Decimal 產生數值事實。這些措施不能保證模型理解了使用者需求；時間、口徑、篩選與數值仍需獨立評估。正式評估後不為提高分數調參重跑。
