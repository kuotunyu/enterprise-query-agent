# v1 開發驗收案例

這些是已公開給實作者的開發案例，不是正式 holdout。下面金額均為合成 BRL；日期與資料身分都不來自真實 Olist 成績。

## 合成資料基線

- O1：2018-07-10，delivered，客戶記錄 C1／自然人 U1，SP；A 品類商品 100＋運費 10、B 品類 50＋5；兩筆付款 100、65；兩筆評論，較早 1 分、較晚 5 分；預估 7/15 12:00，實際 7/16 12:00。
- O2：2018-07-20，delivered，客戶記錄 C2／自然人 U1，SP；A 品類商品 40＋4；付款 44；評論 3 分；預估 7/25 12:00，實際 7/25 12:00。
- O3：2018-07-21，canceled，自然人 U2；A 品類商品 200＋20；付款 220；不能加入 delivered GMV。
- O4：2018-07-22，delivered，自然人 U3，RJ；B 品類商品 30＋3；付款 30，刻意與 GMV 不同；無評論，actual delivery 為 null。
- O5：2018-06-10，delivered，自然人 U4，SP；A 品類商品 100＋10；付款 110；無評論；實際等於預估送達。

日期欄位使用來源 DATETIME 規則。SQL 測試 fixture 的 ID 使用符合來源 schema 的固定 32 字元 hex；上面的 O1／U1 是文件別名。所有非關鍵必填欄位以固定值填入，不能用隨機值改變答案。

| ID | 問題／情境 | 可核對的預期 |
|---|---|---|
| D01 | 2018 年 7 月 delivered 含運 GMV、訂單數與 AOV | 242.00、3、80.666…，展示 80.67；保留未提早 round 的運算值 |
| D02 | 同期不含運商品金額 | 220.00；與 GMV 相差 22.00 |
| D03 | 7 月 GMV 按品類 | A＝154.00、B＝88.00；合計 242.00 |

| D11 | 7 月 AOV 按品類 | A：154/2＝77；B：88/2＝44；O1 跨類別重疊，分組訂單數不可加總成總訂單數 |

| D14 | 使用者先選含運 GMV，再改成不含運 | 最新 revision 答 220.00；遲到的 242.00 結果不覆蓋畫面 |

| D19 | 前期 GMV＝0 的變體 | 回傳絕對差，比例 undefined；無除零、Infinity 或假 100% |
| D20 | partial month 與完整月相比 | 顯示 coverage 限制，按既定 policy 不產生正常月增率 |

## 工程案例

| ID | 情境 | 預期 |
|---|---|---|
| E01 | INSERT／UPDATE／DROP／多語句 | parser 拒絕；另外在隔離 DB 直接用 runtime 帳號驗證無寫入權限 |
| E02 | WITH／子查詢／alias 隱藏其他 schema 的讀取 | 解析實際來源後拒絕；合法 CTE 不被一概當壞查詢 |
| E03 | SELECT INTO OUTFILE、LOAD_FILE、SLEEP、BENCHMARK、locking clauses | 拒絕，不送到業務 DB |
| E04 | 惡意字串作 filter value | 參數化後當資料處理，不改 SQL 結構 |
| E05 | 任務／SQL 超時 | 明確 terminal timeout，查詢實際停止；不只停止 UI spinner |
| E06 | 超過 200 列或結果截斷 | truncated 明示；不從截斷明細算全體總數 |
| E07 | provider error／無效 JSON／未知 metric | 有界失敗／修正，保留錯誤原因與已花成本，不无限重試 |
| E08 | 同一 request_id 網路重送 | 不自行再起第二個等價模型工作；可讀現有 task 狀態 |
| E09 | 全新來源啟動與埠占用 | 可用合成資料啟動；衝突時不停止其他服務、不使用前作 volume |
| E10 | 結果文字含 HTML 或指令 | 純文字顯示，不执行 HTML，不把資料內容升格成工具授權 |
| E11 | 比率／貨幣／時間值 | Decimal 運算、BRL 標示、日期半開區間；null 和 0 區別 |
| E12 | DB 或資料版本不符 | 啟動／查詢明確拒絕，不能從未記錄的資料環境產生成績 |

## 如何驗證而不讓測試複製實作

以以上手算值作固定 oracle；另由獨立 pandas／純 Python 聚合核對至少 D01–D12，不呼叫候選 SQL compiler 產生 gold。準備至少兩個變體：拆分一筆付款成多筆但保持付款總額；新增較舊評論但保持最新評論。GMV／最新評分應不變；可揭露 fan-out 的實質錯誤。

在正式評估前鎖定 Decimal／比例 tolerance、排序 tie-break 和 null 比較。開發數值驗收不依賴模型必然正確；先驗證底層契約，再把自然語言端到端表現作實測結果。三方法都要保留錯答，不能讓測試替模型修正答案而算成功。
